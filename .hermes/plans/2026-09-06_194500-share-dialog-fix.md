# Share-UX-Fix: „Nach unten geschickt + klick-Text am unteren Rand" — Analyse & Plan

**Datum:** 2026-09-06 · Projekt fck_afd

---

## 1. Was Nick beschreibt (Reproduktion)

Beim Tippen auf einen **Teilen-Button** (Scene-Share ↑ an jeder Szene, oder EndCard):

1. Man wird **ans Ende der Seite geschickt** („nach ganz unten geschickt")
2. Dort ist am **unteren Bildschirmrand** ein unauffälliger Text, den man klicken muss, um den Link zu kopieren
3. Das ist umständlich und nicht auffindbar

## 2. Ursache — BESTÄTIGT durch Live-DOM-Debugging (nicht nur Vermutung)

**Reproduktion (headless, mobile 390px):** Share-Tap auf Szene 2 → `window.scrollY` springt **844 → 32005** (Seitenende). Das Sheet-Element liegt bei `top: 844` (unterhalb Viewport), `getComputedStyle().position` = **`static`**.

**Root Cause (verifiziert per DOM-Debugging):**
- `share.js` erzeugt das Sheet nur mit **`id="share-sheet"`** — aber **ohne `class="share-sheet"`**.
- Die CSS-Regel `.share-sheet { position: fixed; z-index: 90; ... }` matcht deshalb **nicht** (`s.matches('.share-sheet')` → `false`, per Debugging bestätigt; inline `position:fixed` setzen greift sofort).
- Folge: Das Sheet liegt im normalen Dokumentfluss **unter der letzten Szene** am Seitenende. `focus()` (Zeile 115) scrollt dann dorthin → „man wird nach ganz unten geschickt", und das Popover wirkt wie „ein Text am unteren Rand".

**Sekundär:** `focus()` ohne `{ preventScroll: true }` scrollt zusätzlich.

## 4. Fix-Plan (Tasks)

### Task 1: Fehlende CSS-Klasse am Sheet ergänzen (der eigentliche Fix)

  sheet.className = 'share-sheet';

- **Verify:** Scrollposition identisch vor/nach Popover-Öffnung.
